# 技能五子棋 Online

带技能的在线五子棋。在经典五子棋基础上加入了灵力系统和 14 个主动技能，
每局开战前各自挑选 6 个装备上阵。支持线上联机、单机挑战 AI、本地同屏双人三种模式。

前后端同源部署，服务端做权威状态校验（客户端无法作弊改棋盘，也改不了自己的技能池）。

## 快速开始

```bash
npm install
npm start
# 打开 http://localhost:8080
```

Docker：

```bash
docker build -t skill-gomoku-online .
docker run -d --name skill-gomoku -p 8080:8080 --restart always skill-gomoku-online
```

## 玩法

### 灵力

- 黑方（先手）初始 **1** 点灵力，白方（后手）初始 **2** 点，作为先手补偿
- 每回合正常结束时 **+1**，上限 8
- 唯一惩罚：踩中敌方隐身棋时，本回合作废且**不回灵力**
- 带橙色圆圈的棋子是对方上一手刚落的，受保护，不能被吹走或策反

### 技能装备

开战前每人从下面 11 个技能里**挑选 6 个**，对局中只能用自己装备的这几个。

- 线上模式：点「创建随机房」或「加入」时先弹出选择界面，选完才真正进房
- 本地模式：黑方先选，白方后选（挑战 AI 时由 AI 随机）
- 选择会被记住，下次进房自动预填，改完直接确认
- 「重开」沿用上一局的装备，想换装备点重新选技能

服务端会校验数量、去重、技能 id 合法性，
**未装备的技能发过来会被直接拒绝**，改前端没用。

### 模式

- **线上联机**：创建随机房（6 位房间码，剔除 0/O/1/I 等易混字符）或输入好友的房间码
- **挑战 AI**：本地对电脑
- **本地双人**：同一屏幕轮流落子

## 技术栈

- 后端：Node.js + Express + Socket.IO，单文件 `server.js`
- 前端：原生 JS + Canvas，无框架
- 部署：Docker（node:22-alpine，非 root 运行，带健康检查）

## 关键实现

**服务端权威**：所有落子、技能、胜负判定都在服务端执行，
客户端只发意图（`boardAction`），收状态（`syncState`）。

**技能装备校验**：技能能不能用由服务端判断，链路是

```
SKILL_DEFS 里存在 → 在自己 6 个装备里 → 灵力够 → 没被沉默
```

前端把按钮置灰只是体验，改前端发未装备的技能会被直接拒。

**信息隔离**：`getClientState()` 按视角过滤。
隐形棋和诡雷对手都看不到（观战者可见全部，方便看局）。

**回合状态机**：`phase` 分为 `picking`（选技能）/ `playing` / `over`。
`picking` 阶段禁止落子。进房时可直接携带 `loadout` 一步到位，
后进房的玩家也允许补选（避免先 ready 的人开局后对手卡死）。

**延迟播报**：`nextTurn()` 只负责推进计时（隐形棋显形、墨染腐化、
沉默解除），结果推进到 `state.expiredStealths / expiredInks`，
由 `broadcastRoom()` 统一播报——因为只有那里拿得到 `room` 对象。

**断线重连**：进房下发 `session`（token + 角色），
前端存 localStorage，刷新后凭 token 恢复原座位，座位保留 90 秒。

**聊天安全**：聊天内容会拼进 `innerHTML`，前端用 `escapeHtml()` 转义，
防 XSS。

**房间生命周期**：30 分钟无活动自动清理，避免长期运行内存堆积。

## 测试

`tools/` 下是从开发过程中沉淀的 socket.io 客户端测试，直接连真实服务跑：

```bash
bash tools/run-all.sh          # 跑全部本地套件
node tools/browser-sim.js http://<host>/   # 模拟浏览器加载 + WebSocket
```

覆盖：通用对局流程、飞沙吹歪、护盾挡击、日志聊天、断线重连、隐身时效、
技能装备与三个新技能（诡雷引爆、沉默、墨染腐化）。

## 已知限制

- 房间和日志都在内存里，服务重启即丢失
- AI 目前只有单点评分，不会用技能，也看不懂双三/四三这类复合威胁
- 无 HTTPS，若部署在子路径下需要反代处理 WebSocket 升级
